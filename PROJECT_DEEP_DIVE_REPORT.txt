1. EXECUTIVE SUMMARY & SYSTEM OVERVIEW
====================================================================================================
FinPulse AI is an enterprise-grade hybrid quantitative
finance and personal financial intelligence system. It combines:
1. Point-in-time market data ingestion and technical feature engineering.
2. Gradient-boosted tree modeling (XGBoost) for forward 5-day equity directional movement.
3. Realistic, vectorized, non-overlapping backtesting incorporating transaction friction.
4. Deep time-series probabilistic forecasting (Prophet, N-BEATS, N-HiTS, TFT) and Monte Carlo
   what-if scenario simulations.
5. A 4-layer anomaly and fraud detection engine combining statistical methods, unsupervised
   machine learning, sequence autoencoders, and an XGBoost meta-classifier.
6. A ReAct (Reasoning + Acting) autonomous agent framework for financial actions (bill negotiation,
   subscription watchdog, auto-balancing).
7. Privacy-preserving Federated Learning (FedAvg) and Explainable AI (SHAP attributions & reasoning traces).
8. A modern, dark-mode, responsive web interface built with React 19, TypeScript, and Vite.

Academic Integrity & Engineering Philosophy:
- Zero Look-Ahead Bias: All technical indicators are calculated strictly on data <= t.
- Strict Chronological Splitting: 70% Train, 15% Validation, 15% Out-of-Sample Test partition.
- Naive Baseline Comparisons: Models are benchmarked against random chance, always-majority class,
  and 5-day momentum persistence.
- Tool-First Determinism: The AI Copilot uses deterministic code execution to retrieve balances,
  runway, and metrics rather than allowing the LLM to hallucinate financial arithmetic.

4.2 Synthetic Market Data Generator (Geometric Brownian Motion with Jump-Diffusion):
- Implemented in `backend/app/ml/pipeline/collect_data.py` (`--synthetic` flag).
- Purpose: Fully reproducible offline pipeline execution without requiring active broker tokens.
- Mathematics:
  S_t = S_{t-1} * exp( (mu - 0.5 * sigma^2)*dt + sigma*sqrt(dt)*Z_t ) + J_t
  where:
    - Base starting prices: RELIANCE=2500, HDFCBANK=1600, INFY=1500, TCS=3500 INR.
    - Volatility sigma: 0.22 - 0.26 annualized.
    - Drift mu: 0.10 - 0.14 annualized.
    - Jump process J_t: Poisson probability with random negative or positive price shock.
    - Intraday High/Low/Open bounds: Simulated using realistic daily range distributions.
    - Volume: Log-normal distribution with volatility correlation.
- Output: Stored strictly at `backend/app/ml/pipeline/data/sample/synthetic_market_dataset.parquet`.

5.1 CORE MARKET DIRECTIONAL CLASSIFIER (XGBoost 3-Class)
----------------------------------------------------------------------------------------------------
Location: `backend/app/ml/pipeline/`
Pipeline scripts:
  - `build_features.py` -> 13 point-in-time features
  - `build_targets.py` -> 5-day forward return & direction labeling
  - `train_xgboost.py` -> Model training & baseline evaluation
  - `backtest.py` -> Out-of-sample vectorized execution simulation

Mathematical Formulation:
- Observation at Day t Close (15:30 IST):
  Feature vector X_t is computed strictly from historical OHLCV data <= t.
- Forward Return Target:
  R_{t -> t+5} = (Close_{t+5} - Close_t) / Close_t
- 3-Class Regime Labeling:
  - "UP":      R_{t -> t+5} > +0.015  (+1.5%)
  - "DOWN":    R_{t -> t+5} < -0.015  (-1.5%)
  - "NEUTRAL": -0.015 <= R_{t -> t+5} <= +0.015

13 Point-in-Time Features:
  1. `return_1d`: Daily price percentage change: (Close_t - Close_{t-1}) / Close_{t-1}
  2. `return_5d`: 5-day rolling price change: (Close_t - Close_{t-5}) / Close_{t-5}
  3. `return_20d`: 20-day rolling price change: (Close_t - Close_{t-20}) / Close_{t-20}
  4. `volatility_20d`: Rolling 20-day sample standard deviation of daily returns annualized (sqrt(252))
  5. `sma_20`: 20-day Simple Moving Average of Close
  6. `sma_50`: 50-day Simple Moving Average of Close
  7. `sma_200`: 200-day Simple Moving Average of Close
  8. `rsi_14`: 14-day Relative Strength Index (gain/loss Wilder smoothing)
  9. `macd`: Moving Average Convergence Divergence line: EMA_12(Close) - EMA_26(Close)
  10. `macd_signal`: 9-day EMA of MACD line
  11. `bollinger_upper`: SMA_20 + 2 * std_20
  12. `bollinger_lower`: SMA_20 - 2 * std_20
  13. `relative_volume`: Volume_t / SMA_20(Volume)

Chronological Splitting Constraint:
  Total dates sorted strictly in ascending order:
  - Train Set (70%): 15,270 rows (2000-10-06 to 2016-12-13)
  - Validation Set (15%): 3,472 rows (2016-12-14 to 2020-06-24)
  - Test Set (15%): 3,476 rows (2020-06-25 to 2023-12-21)
  Strict constraint: max(Train_Date) < min(Val_Date) < min(Test_Date).
  The test set is completely untouched during feature scaling and hyperparameter fitting.

Hyperparameters (XGBoost):
  - Model: `xgb.XGBClassifier`
  - `n_estimators`: 100
  - `max_depth`: 4
  - `learning_rate`: 0.03
  - `subsample`: 0.8
  - `colsample_bytree`: 0.8
  - `random_state`: 42
  - `objective`: "multi:softprob" (outputs normalized probability distribution over 3 classes)
  - `eval_metric`: "mlogloss"
  - Sample Weighting: Unweighted to maintain true market empirical probability calibration.

Feature Importance Hierarchy (Test Partition):
  1. `volatility_20d` (11.66% importance)
  2. `bollinger_lower` (9.77% importance)
  3. `sma_50` (8.75% importance)
  4. `sma_200` (8.55% importance)
  5. `bollinger_upper` (8.20% importance)
  6. `sma_20` (7.77% importance)
  7. `return_5d` (7.63% importance)
  8. `return_20d` (7.35% importance)
  9. `macd` (6.75% importance)
  10. `macd_signal` (6.56% importance)
  11. `return_1d` (6.12% importance)
  12. `rsi_14` (5.54% importance)
  13. `relative_volume` (5.36% importance)

5.2 TIME-SERIES & CASH FLOW FORECASTING ENGINES
----------------------------------------------------------------------------------------------------
FinPulse includes both production services and cutting-edge research forecasting modules:

1. Facebook Prophet Service (`backend/app/ml/forecasting/prophet_service.py`):
   - Formulation: Additive model y(t) = g(t) + s(t) + h(t) + epsilon_t
     - g(t): Piecewise linear trend with automatic changepoint selection.
     - s(t): Fourier series modeling yearly, monthly, and weekly seasonality.
     - h(t): Holiday and payday indicator matrices.
   - Outputs: Point forecast (`yhat`), upper bound (`yhat_upper`), lower bound (`yhat_lower`)
     at 80% and 95% uncertainty intervals.
   - Out-of-sample evaluation: Chronological backtesting calculating MAE and RMSE.

2. Dual-Engine LSTM Deep Recurrent Forecaster (`backend/app/ml/forecasting/lstm_service.py`):
   - Primary Architecture (Keras/TensorFlow Engine):
     Input layer (lookback window = 15-30 days) -> LSTM(32 units, return_sequences=True) -> Dropout(0.15)
     -> LSTM(16 units, return_sequences=False) -> Dropout(0.15) -> Dense(8, activation='relu') -> Dense(1, linear).
     - Optimizer: Adam with EarlyStopping on training loss.
   - Cloud Resilient High-Performance Engine (`_forecast_numpy`):
     - Developed specifically for cloud production environments (such as Render 512MB RAM free-tier containers)
       to avoid heavy C++ compiler overhead, 500MB+ binary wheels, and out-of-memory (OOM) build terminations.
     - Pure NumPy & Scikit-Learn recurrent autoregressive sequence projection with L2 Ridge regularization.
     - Sliding-Window Sequence Formulation:
       X_i = [p_{i}, p_{i+1}, ..., p_{i+k-1}], y_i = p_{i+k}
     - Strict Zero-Leakage Preprocessing: MinMaxScaler is fit ONLY on the training split (first 80%),
       then applied forward to test and projection sequences.
     - Recursive Multi-Step Forward Horizon: Projects 14 to 30 days into the future step-by-step.
     - Out-of-Sample Hold-Out Evaluation: Chronological test window measuring holdout Mean Absolute Error (MAE)
       and Root Mean Squared Error (RMSE).


3. Neural Forecasters v2 (`backend/app/ml/forecasting/v2/`):
   - N-BEATS (`nbeats_forecaster.py`): Neural Basis Expansion Analysis for Time Series. Uses deep
     stacks of fully connected layers with forward and backward residual links (trend and seasonality blocks).
     Requires zero feature engineering.
   - N-HiTS (`nhits_forecaster.py`): Neural Hierarchical Interpolation for Time Series. Employs
     multi-rate data sampling and hierarchical interpolation to capture long horizons efficiently.
   - TFT (`tft_forecaster.py`): Temporal Fusion Transformer. Uses Variable Selection Networks (VSN),
     Gated Residual Networks (GRN), and multi-head self-attention to process both static metadata
     (account tier, risk profile) and dynamic time series with quantile loss (P10, P50, P90).

4. Weighted Dynamic Ensemble (`backend/app/ml/forecasting/v2/ensemble.py`):
   - Evaluates each model on a 30-day chronological holdout window.
   - Calculates Mean Absolute Percentage Error (MAPE).
   - Computes dynamic weights: w_i = (1 / MAPE_i) / sum_j(1 / MAPE_j).
   - Applies exponential weight decay: w_t = 0.95 * w_{t-1} + 0.05 * w_new.

5. Monte Carlo Scenario Engine (`backend/app/ml/forecasting/v2/scenario_engine.py`):
   - Runs 10,000 simulated paths to compute ruin probability and runway duration.
   - Built-in scenarios:
     1. Job Loss (Zero primary income for N months).
     2. Medical Emergency (Lump-sum negative shock).
     3. Market Crash (30-50% equity valuation drop).
     4. Lifestyle Inflation (Discretionary spend increase by X%).
     5. Side Income Boost (Periodic secondary inflow).

5.3 MULTI-LAYER TRANSACTION ANOMALY DETECTION ARCHITECTURE
----------------------------------------------------------------------------------------------------
Location: `backend/app/ml/anomaly/`
Designed to eliminate false-positive fatigue while detecting nuanced fraudulent or erroneous transactions:

- Layer 1: Statistical Detectors (`statistical_detectors.py`):
  - Rolling Z-Score: Identifies deviations > 3 standard deviations from user's 30-day mean.
  - Interquartile Range (IQR): Flags values outside [Q1 - 1.5*IQR, Q3 + 1.5*IQR].
  - Seasonal STL Decomposition: Decomposes series into Trend + Seasonal + Residual, flagging
    residual outliers.

- Layer 2: Machine Learning Detectors (`ml_detectors.py`):
  - Enhanced Isolation Forest: Isolates anomalies in high-dimensional feature space (amount,
    time_since_last_tx, merchant_category_encoded, day_of_week, 7d rolling mean).
    Per-user contamination rate dynamically calibrated (0.01 - 0.05).
  - One-Class SVM: Non-linear boundary using Radial Basis Function (RBF) kernel with nu=0.05.
  - Deep Reconstruction Autoencoder: Neural network (Input 20 -> Dense 64 -> Dense 32 ->
    Latent Bottleneck 16 -> Dense 32 -> Dense 64 -> Output 20). Reconstruction error
    ||x - x_hat||^2 acts as continuous anomaly score.

- Layer 3: Sequence / Temporal Detectors (`sequence_detectors.py`):
  - LSTM Sequence Autoencoder: Encodes sequences of 10 consecutive transactions to catch temporal
    irregularities (e.g., $10 coffee followed immediately by $1,200 electronics in a new city).
  - Transformer Attention Detector: Uses multi-head self-attention over historical transaction
    embeddings to detect long-range behavioral anomalies.

- Layer 4: Meta-Classifier Ensemble (`meta_classifier.py`):
  - XGBoost Stacking Classifier taking input scores from all lower layers.
  - Generates unified anomaly probability [0.0, 1.0].
  - Integrates SHAP (Shapley Additive Explanations) to explain exactly which detector triggered
    the alert.
  - Alert Tiers: INFO (0.3 - 0.5), WARNING (0.5 - 0.7), CRITICAL (> 0.7).

5.5 FEDERATED LEARNING ENGINE (PRIVACY-PRESERVING EDGE COMPUTE)
----------------------------------------------------------------------------------------------------
Location: `backend/app/ml/federated/` & `src/lib/ml/FederatedClient.ts`
- Philosophy: User financial transactions contain sensitive personal data and should not be
  unnecessarily aggregated in cleartext on a centralized server.
- Federated Protocol:
  1. Server distributes global model parameters (`GET /api/v2/federated/global_model`).
  2. Client-side browser runtime (`FederatedClient.ts`) executes local gradient descent on
     local transactions stored in IndexedDB/Zustand.
  3. Client uploads only weight deltas / gradients (`POST /api/v2/federated/submit_update`).
  4. Server performs Federated Averaging (FedAvg):
     w_{t+1} = sum_k (n_k / n) * w_{t+1}^k
  5. The global model improves without raw private data ever leaving the user's browser.

7. VECTORIZED WALK-FORWARD BACKTESTING ENGINE
====================================================================================================
Location: `backend/app/ml/pipeline/backtest.py`
Standard backtests often produce unrealistically high returns due to lookahead leakage, overlapping
positions, and zero slippage assumptions. FinPulse enforces rigorous institutional constraints:

1. Out-of-Sample Test Window:
   Runs strictly on the test partition (the final 15% of historical dates: 2020-06-25 to 2023-12-21+).
2. Vectorized Predictions:
   Predictions are generated across all test observations simultaneously without lookahead row loops.
3. Non-Overlapping Position Lock:
   Because the model predicts 5-day forward directional returns, entering a trade locks that
   instrument for 5 full trading days. The engine forbids entering new positions on the same
   instrument on days t+1, t+2, t+3, t+4. This avoids fictitious compounding of the same price move.
4. Transaction Friction & Slippage:
   An explicit transaction friction parameter is deducted from every trade:
   - 0.10% (10 basis points) roundtrip slippage + brokerage + STT proxy.
   - Net Return = Gross Return - 0.0010.
5. Capital Allocation & Position Sizing:
   - Starting Capital: INR 100,000.00
   - Maximum position size per trade: 25% of active portfolio capital.
   - Benchmark: Equally weighted Buy-and-Hold portfolio across all 4 universe instruments.

====================================================================================================
8. SYSTEM WORKFLOWS & DATA FLOW LIFECYCLES
====================================================================================================

Workflow A: Market Data & ML Directional Forecasting Pipeline
  1. Ingestion: `collect_data.py` calls Upstox v2 API or Yahoo Finance to fetch daily OHLCV bars.
  2. Cleaning: Timestamps normalized to date; missing values checked; Parquet saved to `data/raw/`.
  3. Features: `build_features.py` iterates per instrument group, computing 13 technical features <= t.
  4. Target Formulation: `build_targets.py` calculates R_{t -> t+5}, assigns UP/DOWN/NEUTRAL labels,
     and drops the trailing 5 rows.
  5. Training: `train_xgboost.py` applies chronological 70/15/15 split, fits XGBoost classifier,
     evaluates against naive baselines, and serializes models to `models/xgboost_direction.json`
     and `models/xgboost_direction.joblib`.
  6. Backtesting: `backtest.py` simulates out-of-sample trades with non-overlapping holding and 10 bps friction.
  7. API Serving: `predict.py` and `backend/app/api/v1/markets.py` load artifacts and serve live
     inference via `/api/v1/markets/predictions` and `/api/v1/markets/backtest`.

Workflow B: Streaming Transaction Ingestion & Multi-Layer Anomaly Scoring
  1. Transaction Arrival: Webhook or user manual entry at `POST /api/v1/transactions/`.
  2. Stream Broker: Pushed to `EventBus` topic `transactions.raw`.
  3. Feature Enrichment: Rolling 7-day stats, merchant categorization, and user historical profile attached.
  4. Parallel Scoring:
     - Statistical Detector (Z-score & IQR) runs in < 5ms.
     - ML Isolation Forest & One-Class SVM score in < 25ms.
     - Autoencoder reconstruction error computed.
  5. Stacking Meta-Classifier: XGBoost combines scores; if probability > 0.50, an alert event is
     emitted to `alerts.generated`.
  6. Smart Grouping: Alerts are grouped by merchant and 1-hour time window to avoid spamming the user.
  7. Persistence: Transaction saved to DB; WebSocket / SSE pushes alert to React notification badge.

Workflow C: AI Copilot Question Answering & What-If Simulation
  1. User Prompt: "Can I afford to buy an iPhone 16 Pro this weekend?"
  2. Intent Router & Semantic Item Parser (`item_pricing.py`):
     - Classifies query as `affordability_check`.
     - Automatically parses semantic item descriptions into real-world retail pricing:
       - "iPhone 16 Pro" -> ₹125,000
       - "MacBook Pro" -> ₹199,900
       - "Royal Enfield / Bike" -> ₹220,000
       - "iPad Air" -> ₹59,900
  3. Tool Invocations:
     - `tool_registry.get_net_worth(db)` -> Retrieves checking, savings, liquid investments.
     - `tool_registry.get_runway(db)` -> Computes average monthly burn rate and runway months.
     - `tool_registry.get_upcoming_bills(db)` -> Identifies cash obligations due in next 14 days.
  4. Deterministic Calculation & Offline Fallback:
     - Post-purchase cushion = Checking (₹150,000) - Purchase (₹125,000) = ₹25,000.
     - Safety threshold = Minimum 1 month essential expenses (₹30,000).
     - Result: Caution advised (checking cushion drops slightly below the preferred ₹30,000 threshold).
     - Deterministic Fallback: When external LLM API tokens (Gemini / OpenAI) are unconfigured,
       the engine automatically switches to pure deterministic financial logic with zero hallucinations.
  5. Grounded Generation: Formats structured assessment with exact figures and buttons
     to simulate the impact in the interactive Simulator page (`/app/simulator`).
  6. SSE Streaming: Streamed chunk-by-chunk to the React Copilot chat window.

Workflow D: Cloud Container Resilience & Public Market Ingestion (Render Infrastructure)
  1. Lightweight Container Build:
     - Requirements manifest optimized for 512MB RAM Linux container environments by pruning heavy,
       unnecessary binary packages (`tensorflow`, `keras`, `streamlit`).
     - Fast 20-second builds eliminating Out-Of-Memory (OOM) failures and 15-minute timeout aborts.
  2. Public Market Endpoint Decoupling:
     - Endpoints (`/markets/overview`, `/stocks/top`, `/predictions`, `/analytics`) are completely
       decoupled from user authentication and database connection pools.
     - Public exploration operates with zero database lock contention and zero 401 Unauthorized errors.
  3. Float Sanitization:
     - All incoming OHLCV feeds pass through `_safe_float()`, mapping NaNs to zero or valid floats
       to ensure strict RFC 8259 JSON compliance.
  4. SPA Route Isolation:
     - Fast-fail 404 guard added to `serve_spa()` so missing API endpoints never return `index.html`
       as faux JSON.

11.2 Out-of-Sample Backtesting Summary (Realistic 10 bps Friction):
- Initial Capital: ₹100,000.00
- Final Capital: ₹107,216.67
- Strategy Net Return: +7.22% (136 completed non-overlapping trades, 48.5% win rate)
- Benchmark (Buy & Hold): +8.98%
- Maximum Drawdown: -16.46%
- Transaction Friction: 0.10% (10 bps) per trade slippage and brokerage deduction.

11.3 Mathematical & Financial Limitations:
1. Martingale / Near-Random-Walk Behavior:
   Asset prices over short horizons (1 to 5 days) exhibit low signal-to-noise ratios. Technical
   indicators alone (SMA, RSI, MACD, Bollinger) carry weak directional alpha. An accuracy near 35%
   on a 3-class problem is mathematically normal and consistent with academic literature.
2. Small Instrument Universe:
   The current pipeline focuses on 4 large-cap NIFTY equities. Cross-sectional momentum and mean
   reversion require a broader universe (NIFTY 500) to exploit statistical dispersion.
3. Execution Gap:
   Daily EOD backtesting cannot model intraday order-book depth, bid-ask spread expansion during
   volatility spikes, or overnight gap openings.
4. Non-Advisory Disclaimer:
   This project is an academic engineering and quantitative prototype. It is strictly not financial
   advice or commercial automated trading software.
